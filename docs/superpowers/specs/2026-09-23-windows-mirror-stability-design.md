# Windows 镜像稳定性修复设计

## 目标

修复 Windows 多显示器及虚拟显示驱动环境下，打开或关闭 Android 镜像时的原生崩溃。保持现有镜像交互、日志、性能分析和主题功能不变，并避免要求用户长期禁用向日葵等虚拟显示驱动。

## 根因与边界

当前 Windows 原生镜像插件在 Flutter 栅格线程仍可能读取纹理时立即销毁解码会话，存在释放后访问风险。同时，首页 `media_kit` 背景视频的硬件纹理会在进入设备页时异步释放，可能与镜像纹理创建重叠。虚拟显示驱动会放大这两类 GPU/纹理时序问题，但不是唯一根因。

本次处理：

- Windows scrcpy 像素纹理的停止、注销和销毁顺序。
- 解码器在输入线程与栅格线程之间的并发访问。
- Windows 首页背景视频及虚拟显示驱动的兼容策略。
- 自动更新下载完成后的静默覆盖安装流程。
- 镜像反复启动、停止及异常退出的回归测试。

不改变 Android/iOS 日志、性能指标、设备发现和其他平台的行为。

## 设计

### 原生纹理生命周期

`WinTextureSession` 增加显式停止状态。停止后拒绝新数据和新帧通知，但在 Flutter 纹理注销完成之前保留会话及像素缓冲区。插件使用 `TextureRegistrar::UnregisterTexture` 的完成回调，回调触发后才释放会话。

解码器访问通过互斥保护或稳定的共享所有权完成，保证 `CopyPixelBuffer`、`Feed` 与 `Stop` 不会并发访问已释放对象。帧到达回调在停止状态下直接返回。

### 背景视频兼容策略

Windows 上的首页氛围视频改为软件解码。检测到 Oray、向日葵、SpaceDesk、Parsec 等虚拟显示驱动时，首页不再创建视频纹理，并将 Android 镜像切换到随包提供的官方 scrcpy 独立兼容窗口。这样即使显卡驱动或 SDL 发生异常，也不会带崩 Logbay 主进程；普通电脑仍使用原有内嵌镜像。

### 自动覆盖安装

更新组件只负责下载，不再自动打开交互式安装界面。下载完成后，Logbay 写入一次性 PowerShell 更新脚本，以命名参数传递安装包路径和当前进程号。脚本等待旧进程退出，再以 Inno Setup 静默覆盖参数启动安装程序，最后删除自身。该方式兼容包含空格和中文的安装路径，并避免安装程序被重复启动。

### 错误处理

纹理注册失败时不创建解码器，并向 Dart 返回可理解的错误。重复停止和重复释放必须幂等。纹理注销完成回调不得访问已销毁的插件对象。

## 验证

- 原生单元级检查：创建、推帧、停止、异步注销、回调销毁的顺序。
- Flutter 现有测试全量运行。
- Windows 构建验证。
- 手工验证：普通单屏使用内嵌镜像；向日葵虚拟屏启用状态下启动独立兼容镜像并完成鼠标、键盘控制；两种模式均连续启动/停止 20 次。
- 从旧版本检查更新，验证下载完成后应用自动退出、静默覆盖安装并重新保留唯一的安装记录与快捷方式。

## 成功标准

镜像启动和关闭不再触发 `MSVCP140.dll`/纹理相关原生崩溃；虚拟显示驱动机器使用隔离兼容窗口；更新无需用户再次手动执行安装程序；背景视频、日志和性能采集功能无回归。
